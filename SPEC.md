# Specification — channel access plugin

US-019 of the B2B demo (sprint 7). Standalone plugin: an access mode per channel (open, prices
hidden, closed), enforced on the server. US-020 (registration approval) consumes the contract.
Checked against Sylius 2.3.1 (vendor), twig-hooks 0.14.1, Symfony 7.4.

## 1. Threat model (what the security review should attack)

Assets: the catalogue (names, structure, descriptions), the prices, the ability to buy.
Attackers: an anonymous visitor on a restricted channel.

| # | Bypass attempted | Defence |
|---|---|---|
| 1 | Open a catalogue URL on a closed channel | `VisitorAccessListener` (kernel.request, priority 6, after the firewall at 8): refused unless the route name or the decoded path is in the allow-list; deny by default |
| 2 | Reach a non-existing path to get the 404 page (menu of the catalogue) | The router throws before the listener: `ClosedChannelExceptionListener` (kernel.exception, priority 64) answers `HttpExceptionInterface` of the main request with the same refusal |
| 3 | Climb out of an exempt prefix (`/feeds/../x`, `%2e%2e`, `//`, backslash, NUL) | Path patterns never match a decoded path containing `..`, `//`, `\` or NUL; Symfony rejects backslashes in the URI |
| 4 | Open redirect through `_target_path`, `redirect`, `Referer`, `X-Forwarded-Host`, forged `_locale` | The target is always `login_route` generated by the router; the locale is the request one only if the channel offers it |
| 5 | Prices in pages | Hook conditions (`is_granted(TMONIER_CHANNEL_ACCESS_SEE_PRICES)`) on the Sylius hookables; tests assert no `$12.34` pattern on the home page, product page, taxon listing |
| 5b | Catalogue on the pages a closed channel leaves open (home products, taxon menu in every header, 404/error pages) | Hook conditions `is_granted(TMONIER_CHANNEL_ACCESS_SEE_CATALOG)` on `sylius_shop.homepage.index` (latest_deals, new_collection, latest_products) and the header (`menu`, `taxon_hamburger`); render tests on home, login, register |
| 6 | Prices in the shop API | `PriceHidingNormalizer` (priority 65) removes the four keys added by the Sylius variant normalizer; tests walk the decoded JSON of variant, product and collection |
| 7 | Add to cart | Restricted routes (cart, checkout, order, `/api/v2/shop/orders*`) refuse anonymous visitors on a prices hidden channel; `PriceGuardOrderModifier` decorates `sylius.modifier.order` for every other path (live components, re-order) |
| 8 | Shared cache serving one visitor's page to another | `PrivateCacheListener`: `private, no-store`, `Vary: Cookie, Authorization` on every response of a non-open channel, unless an exempt route is explicitly `public` |
| 9 | Invalid or corrupted mode | Form: `EnumType` refuses unknown values, previous mode kept. Storage: unknown value reads as `closed`. Channel class without the trait: `closed` + error log |
| 10 | Exempting everything by configuration | `*`, `**`, `/*`, `/**` refused by the configuration tree |
| 12 | HTTP request that no channel claims | The resolver fails closed (`closed`); without any HTTP request (console) it is `open` |
| 11 | Locking administrators out | Administration and admin API are in the built-in exemptions (they have their own firewalls) |

Accepted limits (documented in the README): sort-by-price order observable; static files served by
the web server; admin and console never restricted; other price sources in third-party code.

## 2. Design decisions

- **Signed in** = the security token holds a Sylius `UserInterface` (shop customer or admin). An
  administrator logged in the admin firewall is not anonymous for the order modifier (admin order
  creation keeps working). The shop firewall context is separate: an admin browsing the shop
  without a shop session is anonymous there.
- **No HTTP request, no restriction.** A single-channel shop resolves its channel in the console
  too, which would block commands and message handlers; the resolver returns `open` without a
  main request.
- **Hook conditions rather than template overrides**: the Sylius templates stay untouched, so an
  open channel or a signed-in customer renders exactly as before. The `condition` option
  needs twig-hooks 0.14 (Sylius 2.3): Sylius 2.2 is not supported.
- **Closed channel shows no price and no catalogue on the exempt pages** (anonymous): `canSeePrices` is false in every
  mode but `open`.
- **No post-login target** is stored: the user lands on the default page after login (YAGNI;
  avoids a second redirect surface).
- **Entity**: trait + interface on the application's channel class (no change to the Sylius core
  mapping); one additive migration through the Schema API.

## 3. Public contract (frozen for 0.x)

`AccessMode` (stored values `open`, `prices_hidden`, `closed`), `AccessModeResolverInterface`
(5 methods), service `tmonier_channel_access.resolver`, Twig functions, security attribute
`TMONIER_CHANNEL_ACCESS_SEE_PRICES`, configuration keys `login_route`, `exempt_routes`,
`exempt_paths`, parameters `tmonier_channel_access.exempt_routes|exempt_paths`.

## 4. Extension points used by US-020

US-020 decorates `tmonier_channel_access.resolver` (a pending customer is "not signed in"), calls
`VisitorAccessListener::refusalFor()` (service `tmonier_channel_access.listener.visitor_access`) to
turn the anonymous refusal into a 403 for a signed-in pending customer, and prepends its waiting
page route to `exempt_routes`. These two service ids and `refusalFor()` are part of the contract.
Known limit: on a closed channel an unknown URL redirects to the login even for a signed-in
customer (kernel.exception runs when the firewall has not).

## 5. Test strategy

Unit: enum, trait, resolver matrix, pattern matcher, configuration, extension, voter, normalizer,
modifier. Integration: add-to-cart guard with a real request stack, migration column.
Functional: closed channel (allow-list, forged inputs, API, cache headers), prices hidden (pages,
API, cart), admin form. Shop assets must be built for the pages to render.
